---

## 1. Суть домена и задачи

Нужно **работоспособное ПС** для цикла **определения портфеля проектов**: заявки → экспертная и финансовая оценка → многокритериальное ранжирование → отбор при ограничениях → сценарии и утверждение, с **импортом финансовых данных** и прозрачной методикой.  
Не цель фазы и не ядро КР: исполнение проектов, Гантт, enterprise-шина.

Система должна одновременно удовлетворить **количественные пороги бланка** (≥15 ФТ, ≥9 не-CRUD, ≥3 роли, ≥3 бизнес-операции, ≥10 таблиц при РБД, ≥2 компонента, тесты, деплой вне IDE) и **предметную логику** (не «красивый CRUD»).

---

## 2. Обязательные ограничения вуза (`confirmed`)

Сводно (детали и ID — в `assignment-requirements.md`):

1. Работоспособный прототип + ПЗ по структуре разд. 4 (без обязательности §4.5 для всех тем).  
2. Предпроект: участники, процессы, объекты, проблемы; ≥2–3 аналога; ФТ/НФТ + роли и сценарии.  
3. Концептуальная модель; обоснованная архитектура; ≥1 явная межкомпонентная интеграция; ≥2 компонента.  
4. Инфомодель + хранилище; при РБД: ≥10 связанных таблиц (обоснованно), PK/FK, в общем случае 3НФ, ≥5 запросов по связям, атомарность где нужно.  
5. AuthN/AuthZ; ≥3 роли; защита «в объёме проекта».  
6. UI/UX; сквозной сценарий пользователь→результат.  
7. ≥15 ФТ, из них ≥9 не сводятся к CRUD; ≥3 спец. бизнес-операции; поиск/фильтр/сорт; отчётность; валидация и ошибки.  
8. Тесты: модульные + интеграционные + UI-сценарии; запуск без IDE + инструкция.  
9. 3 алгоритма по процессам ПО; приложения: Антиплагиат, листинги алгоритмов, скрипт БД; ведомость.  
10. Графика: позиции 5.1–5.7 (+5.8 условно); рек. объём 5–7 А4.  
11. Сроки: **14.12.2026** сдача; проверки 15.10 (прошла), **15.11**, **10.12**.  
12. Стек не фиксирован; OpenAPI и Docker — рекомендации; микросервисы/CI/облако — только при необходимости.

**Индивидуальная тема (`confirmed` студентом 17.10.2026):**  
«Программное средство формирования и оптимизации портфеля проектов предприятия на основе методов многокритериального анализа и интеграции финансовых данных».

**Не confirmed заданием вуза:** Java, конкретный метод МКА (AHP/TOPSIS/MILP и т.д.) — выбор обосновывается.

## 4. Самые важные нерешённые решения (`unresolved`)

1. **DEC-ARCH-01/02** — зафиксированы предпочтением студента (core+2 сервиса+React); осталось устное «ок» руководителя и решение, не раздувать дальше.  
2. **DEC-MATH-01** — SAW vs TOPSIS (и нужен ли AHP для весов).  
3. **DEC-MATH-02** — решатель (своя ДП / ojAlgo / OR-Tools).  
4. **Q-DOM-01/02** — отрасль демо и модель бюджета (один лимит vs периоды).  
5. **Q-GFX / Q-METHOD** — плакаты и методичка кафедры.  
6. Оформление темы на титуле у руководителя.

Финальные ER, API и план реализации **не** выпускать до закрытия математики (п.2–3) и границ домена (п.4) — либо явного «начинай проектирование».

## 5. Главные риски, способные обесценить дизайн

1. Просроченная 1-я проверка + сжатый ноябрь → нет вертикального среза к 15.11 (R1).  
2. Раздутый scope (много методов + микросервисы) (R2).  
3. CRUD без предметных операций / искусственные таблицы (R3, R4).  
4. Интеграция, которую комиссия сочтёт формальной (R5).  
5. Математика без оракулов / Excel-ловушка NPV (R6).  
6. Тема/методичка не согласованы (R10, R9).

## 6. Повестка следующей фазы (проектирование — после ревью)

**Не начинать кодирование приложения до явного «ок» на этот пакет.**

1. Согласовать с руководителем: оформление темы на титуле, DEC-ARCH-01, DEC-MATH-01, Q-GFX.  
2. Зафиксировать границы v1 (стоп-лист фич).  
3. Детализировать: список ≥15 ФТ с трассировкой на REQ-*; матрица RBAC; BPMN ключевого процесса.  
4. Черновик ER ≥10 сущностей (только обоснованные) + перечень ≥5 join-запросов.  
5. Черновик интеграционного сценария (payload, sequence) и решение по OpenAPI.  
6. Таблица оракулов NPV/МКА/рюкзак (Excel) **до** кода.  
7. Каркас плакатов 5.1–5.7 (эскизы).  
8. Затем — только после отдельного решения — skeleton проекта и вертикальный срез к 15.11.

Ориентир графика (детали — risks / агент E): до 25.10 — freeze решений и backlog; к 15.11 — архитектура, БД, интеграция, UI ключевых экранов; к 10.12 — прототип, тесты, деплой, ПЗ/плакаты; 14.12 — сдача.
