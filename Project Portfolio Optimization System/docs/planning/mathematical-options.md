## 1. Финансовые показатели

Обозначения: $CF_t$ — поток периода $t$; $r$ — ставка дисконтирования; $n$ — горизонт; $I_0$ — инвестиции.

| Показатель | Формула / суть | Допущения и ловушки |
|---|---|---|
| **NPV** | $NPV=\sum_{t=0}^{n} CF_t/(1+r)^t$ | Постоянная $r$; не путать с Excel `NPV()` (дисконтирует с первого аргумента массива) `[РИСК]` |
| **IRR** | $NPV(IRR)=0$ | Множественные корни при смене знаков; нет IRR |
| **MIRR** | $(FV_+/|PV_-|)^{1/n}-1$ | Явные $r_r,r_f$; для курсовой часто $r_r=r_f=r$ `[Р]` |
| **PI** | $PI=1+NPV/I_0$ (при $CF_0=-I_0$) | Сильно коррелирует с NPV → двойной счёт в МКА `[РИСК]` |
| **DPP** | мин. $T$: накопленный дисконтированный CF ≥ 0 | Игнорирует потоки после $T$ |
| **EAA** | $NPV\cdot r(1+r)^n/((1+r)^n-1)$ | Для разной длительности; с NPV — двойной счёт |

**Набор без сильного двойного счёта `[Р]`:** NPV + (MIRR **или** IRR) + DPP + **нефинансовые** критерии. **Не** ставить одновременно NPV и PI как отдельные критерии МКА.

**Деньги в коде `[Р]`:** только `BigDecimal` (+ зафиксированные scale/RoundingMode), не `double`.

## 3. Методы МКА (сравнение, без финального выбора)

| Метод | Входы → выход | Плюсы | Минусы / ловушки | Сложность Java |
|---|---|---|---|---|
| **SAW / WSM** | норм. оценки + веса → score | Прозрачность | Сильная компенсация | Низкая |
| **AHP** | pairwise → веса (+ CR) | Экспертная логика | $O(m^2)$ суждений; rank reversal | Средняя |
| **TOPSIS** | матрица + веса → близость к идеалу | Интуитивно | Rank reversal; чувствителен к нормализации | Средняя |
| **VIKOR** | $S,R,Q$, параметр $v$ | Компромисс | Интерпретация $v$ | Средняя |
| **PROMETHEE II** | функции предпочтения | Гибкость | Много параметров | Высокая |
| **ELECTRE** | outranking, veto | Реалистичные вето | Сложные пороги | Высокая |

**Веса:** прямое назначение; AHP; энтропия (объективные); SWARA/BWM (кратко).  
`[РИСК]` энтропия завышает «шумные» критерии.  
`[Р]` зафиксировать одну схему нормализации (min-max **или** векторная для TOPSIS) и показать в ПЗ влияние смены схемы (1 таблица).

## 4. Оптимизация портфеля

Модель 0-1 (одно/много ограничений):
$$
\max \sum_i c_i x_i \quad
s.t.\ \sum_i a_{ki}x_i \le b_k,\quad x_i\in\{0,1\}
$$
плюс: обязательные $x_j=1$; взаимоисключение $x_p+x_q\le 1$; зависимость $x_b\le x_a$.

| Подход | Когда | Замечание |
|---|---|---|
| Полный перебор | $n\le 20$ как оракул | Для тестов |
| ДП / ветви и границы | малый $n$, 1 бюджет | Своя реализация возможна |
| ILP/MIP (решатель) | несколько ограничений + логика | Точность |
| Жадный по $c_i/a_i$ | baseline | Неоптимален при $K>1$ |
| ГА / Timefold | большой $n$ | Часто overkill для КР |

**Java-решатели (лицензии по проверке агента C, уточнять на сайте перед фиксацией):**  
OR-Tools — Apache-2.0 (нативные бинарники); ojAlgo — MIT (pure Java); Choco — BSD; Timefold Community — Apache-2.0.

**Двухэтапная схема** «МКА-score → рюкзак» vs **Парето/ε-ограничения:**  
`[Р]` для курсовой — двухэтапная; Парето NPV–риск — в §4.5 как развитие.  
`[РИСК]` суммировать TOPSIS-closeness по проектам как аддитивную ценность — спорно (зависимость от состава альтернатив); лучше явно описать допущение или использовать SAW-score / NPV в целевой функции.

## 5. Риск

Варианты от простого к сложному: экспертный балл риска как cost-критерий; 3 сценария CF; Monte Carlo / ковариации — обычно лишнее.  
`[РИСК]` двойной учёт: risk-adjusted $r$ **и** отдельный критерий риска.  
`[Р]` либо риск в МКА, либо ограничение $\sum risk_i x_i\le R_{\max}$, не оба агрессивно.

## 6. Валидация реализации

- Эталон Excel/ручной расчёт (учесть семантику Excel NPV).  
- $NPV(IRR)\approx 0$.  
- Рюкзак vs полный перебор при $n\le 20$.  
- Инварианты: $\sum w=1$; масштабирование benefit-критерия; бюджет не превышен; tie-break зафиксирован.  
- Чувствительность: $\pm\Delta r$, $\pm\Delta w$, смена нормализации.
