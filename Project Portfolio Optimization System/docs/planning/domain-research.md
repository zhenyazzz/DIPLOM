# Предметная область: управление портфелем проектов предприятия (PPM)

**Статус решений:** домен **универсальный** (`confirmed` студентом 18.10.2026 — без привязки к отрасли); роли — `proposed`; финальная модель данных — `unresolved`.  
**Связь с заданием:** REQ-PRE-01, REQ-PRE-03, REQ-PRE-06, REQ-MIN-02/04/07/08.  
**Метки:** `[Ф]` факт с источником · `[ТП]` типичная практика · `[Р]` рекомендация · `[Д]` допущение.

---

## 1. Проблема и границы

**Проблема.** Предприятию нужно в рамках бюджетного цикла отобрать и обосновать набор проектов (портфель) при нескольких критериях (финансы, стратегия, риск) и ресурсных/логических ограничениях. Типичный AS-IS — разрозненные Excel, субъективный отбор, слабая воспроизводимость и долгий пересчёт при урезании бюджета `[ТП]`.

**Входит в систему `[Р]`:** стратегические цели периода; заявки-кандидаты; экспертная и финансовая оценка; скрининг; многокритериальная приоритизация; оптимизация состава при ограничениях; сценарии «что если»; утверждение; укрупнённая ребалансировка; отчёты.

**Исключается `[Р]`:** детальный Гантт и критический путь; табели; пофамильное управление людьми; полноценный benefits realization; финансовые портфели ценных бумаг (ISO 21504 исключает их из области `[Ф]` аннотация iso.org); полноценная ERP в реальном времени.

**Обоснование границ:** ISO 21504:2022 — guidance по portfolio management, не по управлению отдельными проектами `[Ф]` https://www.iso.org/standard/82867.html; PMI *Standard for Portfolio Management* (4-е изд., 2017) — balancing, optimization, authorization `[Ф]` (полная сверка страниц — открытый вопрос); MoP (Understand–Categorize–Prioritize–Balance–Plan) — по вторичным источникам `[ТП]`.

## 2. Заинтересованные лица и роли (`proposed`)

| Роль | Цель | Ключевые действия |
|---|---|---|
| Инициатор | Получить финансирование | Подать/доработать заявку, потоки, бюджет |
| Эксперт | Независимая оценка | Баллы по критериям |
| Аналитик портфеля (PMO + финансы) | Методика, импорт, оптимизация, сценарии | Критерии/веса, ограничения, запуск расчётов |
| ЛПР (инвесткомитет) | Утвердить портфель | Утвердить / вернуть / force-in/out с обоснованием |
| Администратор | Доступ и справочники | Пользователи, роли |

Для порога ≥3 ролей (REQ-MIN-04) минимум: **Инициатор / Аналитик / ЛПР** (+ Админ желателен).  
`unresolved`: объединять ли финансового аналитика с PMO; коллегиальное голосование или один ЛПР.

## 3. Процессы

**Жизненный цикл заявки `[Р]`:**  
Черновик → Подана → Экспертиза → Финпроверка → Скрининг / Отклонена → Ранжирована → В сценарии → Утверждена / Отложена / Отклонена → (ребалансировка).

**Сценарий портфеля:** Черновик → Рекомендован → Утверждён / Отклонён → Архив.

**AS-IS `[ТП]`:** разнородные шаблоны; ручной NPV; веса не зафиксированы; «кто громче спонсор»; протокол без трассировки причин отказа.

**TO-BE `[Р]`:** единая форма; импорт потоков; единая ставка; независимая экспертиза; скрининг с причиной; МКА + оптимизация с ограничениями; сравнение сценариев; утверждение с аудитом.

**Ключевой процесс для GFX-02 / BPMN:** «Формирование и утверждение портфеля на бюджетный период».  
AS-IS/TO-BE уместны (REQ-PRE-06) — реальное совершенствование процесса отбора, не формальный реинжиниринг ради галочки.

---

## 4. Решения, которые должна поддерживать система

1. Какое подмножество проектов включить при бюджетном (и др.) ограничении.  
2. Почему проект не вошёл (бюджет периода / взаимоисключение / скрининг).  
3. Что если бюджет −20%.  
4. Что если появился обязательный (регуляторный) проект.  
5. Устойчивость ранга к весам.  
6. Сравнение 2–3 сценариев по KPI.  
7. Ребалансировка после нового прогноза.

## 5. Глоссарий (фрагмент)

| Рус | Eng | Комментарий |
|---|---|---|
| Портфель | Portfolio | Группа проектов/программ для стратегических целей `[Ф PMI]` |
| Заявка / кандидат | Proposal / candidate | Ещё не авторизованный проект `[ТП]` |
| Критерий / вес | Criterion / weight | Признак и относительная важность |
| Скрининг | Screening | Пороговый отсев до ранжирования |
| Сценарий портфеля | Portfolio scenario | Вариант состава при заданных параметрах |
| NPV / IRR / PI / DPP | — | Финансовые показатели (см. `mathematical-options.md`) |
| Обязательный проект | Mandatory / regulatory | Включается вне конкурса `[ТП]` |
| Взаимоисключение / зависимость | Mutually exclusive / dependency | Логические ограничения |
| Эффективная граница | Efficient frontier | Недоминируемые портфели «ценность–затраты/риск» `[Ф PMI; Markowitz — идея]` |
| Ребалансировка | Rebalancing | Пересмотр утверждённого состава |

Полный глоссарий расширяется в ПЗ §4.1.1.

## 6. Кандидаты в информационные объекты (не финальная схема)

Честно без искусственного раздувания набирается **~13–16** сущностей → порог REQ-DB-04 достижим.

**Ядро:** Пользователь; Подразделение; Бюджетный период; Стратегическая цель; Заявка; Связь заявка–цель; Критерий; Методика/веса периода; Назначение эксперта; Экспертная оценка; Денежный поток (строка); Сессия импорта (+ ошибки); Связь проектов (зависимость/исключение); Сценарий; Состав сценария; Решение комитета.

**Опционально:** тип ресурса + мощность + потребность; история статусов; аудит; курсы валют.

**Не раздувать:** отдельный реестр рисков (достаточно критерия); «таблица NPV» как сущность (снимок в сценарии); роли как отдельные таблицы без необходимости.

## 7. Операционные сценарии (для демо и тестов)

1. Годовой/квартальный отбор ~20–30 ИТ-проектов при лимитах.  
2. Урезание бюджета на 20%.  
3. Появление обязательного регуляторного проекта.  
4. Импорт обновлённых денежных потоков с отчётом об ошибках.  
5. Сравнение сценариев «макс. NPV» vs «макс. стратегия».  
6. Чувствительность весов.

---

## 8. Кандидаты ≥9 предметных (не-CRUD) функций

1. Расчёт финансовых показателей (NPV, IRR/MIRR, PI, DPP).  
2. Импорт финансовых данных с валидацией и журналом.  
3. Агрегация экспертных оценок.  
4. Скрининг по правилам с объяснением.  
5. Многокритериальное ранжирование (метод — `unresolved`, см. math).  
6. Оптимизация состава портфеля при ограничениях.  
7. Построение/сравнение сценариев («что если»).  
8. Анализ чувствительности весов (минимум).  
9. Ребалансировка / объяснение невключения.  
10. Утверждение сценария с версией и блокировкой.  
11. (опц.) AHP-веса с CR; покрытие стратегических целей в отчёте.

**≥3 бизнес-операции `[Р]`:** «Сформировать рекомендуемый портфель»; «Утвердить сценарий»; «Ребалансировать при изменении бюджета».

**3 алгоритма для DOC-437 `[Р]`:** (1) финансы NPV/IRR; (2) МКА; (3) 0-1 оптимизация портфеля.
