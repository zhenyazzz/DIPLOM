# 001 — FTS (file transfer service)

## Цель

Отдельный Spring Boot сервис — единственная обёртка над MinIO. Остальные сервисы работают только с `fileId`.

## Не входит

Версионирование файлов, шаринг, ACL на уровне файла, антивирус, multipart-upload чанками, прямой доступ сервисов к MinIO.

## Решения

- Стек как у остальных сервисов: Java 25, Spring Boot 4.1.x, Maven `fts-api` + `fts-impl`, Lombok, MapStruct.
- `common-security` — JWT validate-only; `common-web` — только `BaseEntity` (CRUD-кит не используется).
- Метаданные в PostgreSQL, схема `fts` (тот же инстанс PG), Flyway. Байты — MinIO.
- Бакеты: `IMPORTS`, `REPORTS`, `ATTACHMENTS` → имена `fts-imports`, `fts-reports`, `fts-attachments`; создаются на старте.
- Политика на бакет: `max-size` + allow-list `content-types` (конфиг).
- Ключ объекта = UUID, имя файла от клиента — только метаданные. sha256 считается при загрузке потоком.
- Файл неизменяем. Удаление — soft-delete (`deleted_at`), удалённый = 404.
- Удалить может только загрузивший или `ADMIN`. Читать — любой аутентифицированный.
- Presigned URL подписывается под `fts.minio.public-endpoint` (адрес, видимый браузеру), TTL из конфига.
- Ошибки — RFC 9457 `ProblemDetail` + свойство `code`.

## API (`/api/v1/files`)

| Метод | Путь | Ответ |
|-------|------|-------|
| POST | `/` multipart: `bucket`, `file` | 201 `FileResponse` |
| GET | `/{id}` | 200 `FileResponse` |
| GET | `/{id}/content` | 200 поток, `Content-Type`, `Content-Disposition` |
| POST | `/{id}/download-url` | 200 `DownloadUrlResponse` |
| DELETE | `/{id}` | 204 |

Коды ошибок: `FILE_NOT_FOUND` 404, `EMPTY_FILE` 400, `CONTENT_TYPE_NOT_ALLOWED` 415, `FILE_TOO_LARGE` 413,
`FORBIDDEN` 403, `STORAGE_UNAVAILABLE` 503, `BAD_REQUEST` 400 (валидация/параметры).

## Готово, когда

- `mvn verify` в `services/fts` зелёный (unit + integration на Testcontainers Postgres + MinIO).
- `docker compose up` поднимает postgres + minio; `docker compose --profile apps up` — ещё и fts.
- Контракт `contracts/openapi/fts-v1.yaml` соответствует коду.
